## 1. Введение

Современные пункты проката игровых консолей сталкиваются с необходимостью вести учёт оборудования, клиентов и заказов. При ручном учёте неизбежно возникают ошибки: двойное бронирование одной консоли, некорректный расчёт суммы, потеря истории заказов. Автоматизация этих процессов позволяет сократить время обслуживания клиента и исключить ошибки персонала.

В данной работе разработано настольное приложение — автоматизированное рабочее место (АРМ) специалиста сервиса аренды PlayStation 5. Приложение позволяет оформлять аренду, управлять статусами заказов и вести журнал операций.

## 2. Постановка задачи

**Цель:** разработать desktop-приложение для автоматизации работы специалиста пункта проката PS5.

**Задачи:**

1. Реализовать ввод данных клиента (ФИО, телефон, документ).
2. Реализовать выбор свободной консоли из каталога.
3. Реализовать выбор дат аренды и дополнительного оборудования (геймпады, игры).

5. Реализовать создание заказа и его отображение в таблице.
6. Реализовать управление жизненным циклом заказа (переходы статусов).
7. Реализовать OpenGL-визуализацию состояний консолей.
8. Реализовать экспорт журнала заказов в формат CSV.
9. Разработать UML-диаграмму классов.

## 3. Описание предметной области

**Предметная область** — сервис аренды игровых консолей PlayStation 5.

**Основные понятия:**

- **Консоль (ConsoleDevice)** — единица оборудования для аренды. В системе предусмотрено три консоли PS5. Каждая консоль имеет статус: `Свободна`, `Забронирована`, `В аренде`, `Проверка возврата`, `Недоступна`.

- **Клиент (Client)** — физическое лицо, оформляющее аренду. Идентифицируется по ФИО, телефону и номеру документа.

- **Заказ (RentalOrder)** — договор аренды между клиентом и сервисом. Содержит данные клиента, выбранную консоль, даты, дополнительное оборудование и игры.

- **Жизненный цикл заказа** — последовательность статусов от создания до завершения или отмены:
  `Создан → Активен → Проверка возврата → Завершён` (с возможностью отмены на ранних этапах).

- **Дополнительное оборудование:** геймпады (до 3 шт.) и игры (5 наименований в каталоге).

## 5. Архитектура программы

Программа построена на основе классической архитектуры **MVC (Model-View-Controller)** в варианте, типичном для Qt-приложений:

- **Model** — классы `Client`, `ConsoleDevice`, `Game`, `RentalOrder` и менеджер `RentalManager`. Хранят данные и реализуют бизнес-логику.
- **View** — `MainWindow` с виджетами Qt (таблица заказов, форма ввода, кнопки) и `ConsoleOpenGLWidget` (OpenGL-визуализация).
- **Controller** — слоты `MainWindow`, реагирующие на события кнопок и делегирующие операции в `RentalManager`.

**Ключевые архитектурные решения:**

1. `RentalManager` изолирует бизнес-логику от UI. `MainWindow` не работает напрямую с консолями и заказами — только через методы менеджера.
2. `RentalOrder` хранит **снимки** (копии) объектов `Client` и `ConsoleDevice` на момент создания заказа. Это защищает историю заказов от последующих изменений.
3. GUI строится полностью программно, без `.ui`-файлов Qt Designer. Это упрощает портируемость и понимание кода.
4. `ConsoleOpenGLWidget` получает данные через метод `updateConsoles()` и самостоятельно перерисовывается — никакой прямой зависимости от `RentalManager`.

## 6. Описание классов

### 6.1 Client

Хранит персональные данные арендатора.

**Поля:**
- `m_fullName` — ФИО клиента
- `m_phone` — номер телефона
- `m_documentNumber` — номер удостоверяющего документа

**Методы:** геттеры и сеттеры для каждого поля (`getFullName()`, `setPhone()` и т.д.).

---

### 6.2 ConsoleDevice

Описывает игровую консоль PS5.

**Поля:**
- `m_id` — уникальный идентификатор (1, 2, 3)
- `m_name` — название (`PS5 #1`, `PS5 #2`, `PS5 #3`)
- `m_pricePerDay` — цена аренды в сутки (500 ₽)
- `m_status` — текущий статус (перечисление `ConsoleStatus`)

**Перечисление `ConsoleStatus`:**
```cpp
enum class ConsoleStatus { Free, Reserved, Rented, CheckReturn, Unavailable };
```

**Метод `getStatusText()`** возвращает текстовое представление статуса на русском языке.

---

### 6.3 Game

Описывает игру из каталога дополнительных услуг.

**Поля:**
- `m_id` — идентификатор
- `m_title` — название игры
- `m_pricePerDay` — цена проката в сутки

В системе инициализируется 5 игр: Spider-Man 2, God of War Ragnarök, Horizon Forbidden West, Gran Turismo 7, Demon's Souls.

---

### 6.4 RentalOrder

Центральный класс системы — представляет заказ аренды.

**Поля:**
- `m_orderId` — уникальный номер заказа
- `m_client` — снимок данных клиента (объект `Client`)
- `m_console` — снимок состояния консоли (объект `ConsoleDevice`)
- `m_startDate`, `m_endDate` — даты начала и окончания аренды (`QDate`)
- `m_extraGamepads` — количество дополнительных геймпадов
- `m_selectedGames` — список выбранных игр (`QVector<Game>`)
- `m_rentalStatus` — текущий статус заказа (перечисление `RentalStatus`)

**Перечисление `RentalStatus`:**
```cpp
enum class RentalStatus { Created, Active, CheckReturn, Completed, Canceled };
```

**Ключевые методы:**
- `getDaysCount()` — количество дней аренды (разница дат)
- `getTotalPrice()` — итоговая сумма по формуле
- `getRentalStatusText()` — текстовый статус на русском языке

**Статический метод `gamepadPricePerDay()`** возвращает цену одного геймпада в сутки (150 ₽).

---

### 6.5 RentalManager

Уровень бизнес-логики. Агрегирует все коллекции данных.

**Коллекции:**
- `m_consoles` — три консоли PS5
- `m_games` — пять игр
- `m_orders` — журнал всех заказов

**Публичные методы управления:**
- `createOrder(...)` — создаёт заказ, переводит консоль в `Reserved`
- `calculatePrice(...)` — рассчитывает стоимость без создания заказа
- `startOrder(orderId)` — переводит заказ в `Active`, консоль в `Rented`
- `sendToReturnCheck(orderId)` — переводит в `CheckReturn`
- `completeOrder(orderId)` — завершает аренду, консоль становится `Free`
- `cancelOrder(orderId)` — отменяет заказ, консоль освобождается
- `exportOrdersToCsv(filePath)` — сохраняет журнал в CSV-файл

**Приватные вспомогательные методы:**
- `initConsoles()`, `initGames()` — инициализация тестовых данных
- `findOrderIndex(orderId)`, `findConsoleIndex(deviceId)` — поиск по коллекциям

Наследует `QOpenGLWidget`. Отвечает за OpenGL-визуализацию трёх консолей.

## 9. Описание OpenGL-визуализации

OpenGL-рендеринг реализован с использованием OpenGL Legacy (GL_QUADS, GL_LINES) — без шейдеров, что соответствует уровню учебного проекта.

### Порядок отрисовки одной карточки (`drawConsoleCard`)

1. Фон карточки закрашивается цветом, соответствующим статусу консоли
2. Тёмная рамка карточки (GL_LINE_LOOP)
3. Вызов `drawPS5Silhouette()` для отрисовки силуэта
4. Текстовые надписи через `QPainter` (поверх OpenGL)

### Силуэт PS5 (`drawPS5Silhouette`)

Силуэт состоит из нескольких примитивов GL_QUADS:
- Левая часть корпуса (скошенная трапеция)
- Правая часть корпуса (зеркальная)
- Центральная тёмная полоса
- Нижняя деталь
- Синяя LED-линия
- Две ножки-подставки

### Цветовая схема

```
Свободна       → зелёный  (0.2, 0.8, 0.2)
Забронирована  → синий    (0.2, 0.5, 0.9)
В аренде       → оранжевый (0.95, 0.6, 0.1)
Проверка возврата → красный (0.9, 0.2, 0.2)
Недоступна     → серый    (0.5, 0.5, 0.5)
```

## 10. Алгоритм расчёта стоимости аренды

Метод `RentalManager::calculatePrice()` реализует следующий алгоритм:

```
1. Определить количество дней: days = endDate - startDate (в днях)
2. Если days ≤ 0 → вернуть 0
3. Получить цену консоли: consolePrice = console.getPricePerDay()
4. Стоимость геймпадов: gamepadCost = extraGamepads × 150
5. Стоимость игр: gameCost = сумма (game.getPricePerDay()) по всем выбранным играм
6. Итого: totalPrice = (consolePrice + gamepadCost + gameCost) × days
7. Вернуть totalPrice
```

**Пример расчёта:**
- Консоль: 500 ₽/день
- 2 геймпада: 2 × 150 = 300 ₽/день
- 2 игры (Spider-Man 2 за 200 и God of War за 200): 400 ₽/день
- Итого за день: 1200 ₽
- За 3 дня: **3600 ₽**

## 11. Жизненный цикл заказа

Переходы между статусами реализованы в `RentalManager` как отдельные методы. Каждый метод:
1. Находит заказ по `orderId`
2. Проверяет, что текущий статус позволяет переход
3. Меняет статус заказа
4. При необходимости меняет статус консоли

**Таблица переходов:**

| Метод | Текущий статус заказа | Новый статус заказа | Статус консоли |
|-------|-----------------------|---------------------|----------------|
| `startOrder` | `Created` | `Active` | `Reserved → Rented` |
| `sendToReturnCheck` | `Active` | `CheckReturn` | `Rented → CheckReturn` |
| `completeOrder` | `CheckReturn` | `Completed` | `CheckReturn → Free` |
| `cancelOrder` | `Created` или `Active` | `Canceled` | `Reserved/Rented → Free` |

## 12. Автоматизация возврата и договор аренды

### Зачем нужен договор

В реальном сервисе аренды факт выдачи оборудования клиенту должен быть зафиксирован юридически. Договор подтверждает, что клиент принял консоль в определённом состоянии и несёт ответственность до момента её возврата. Без закрытого договора нельзя считать аренду завершённой — возможные претензии по состоянию консоли должны быть рассмотрены прежде, чем обязательства сторон прекратятся.

В учебном проекте договор реализован программно как класс `RentalContract` со статусами: `Подписан → Активен → Закрыт` (или `Ручная проверка`).

### Почему договор закрывается только после проверки

Договор не может быть закрыт в момент физического возврата консоли, поскольку её состояние ещё не проверено. Только после того как:
1. Автоматическая техническая проверка подтвердила исправность оборудования,
2. Специалист зафиксировал внешнее состояние (фото/видео),
3. Внешнее состояние не требует дополнительной экспертизы,

— договор переходит в статус `Закрыт`. До этого момента он остаётся действующим.

### Как работает имитация бокса (`ReturnBoxSimulator`)

Класс `ReturnBoxSimulator` моделирует внешний диагностический стенд. Метод `runFullCheck()` последовательно вызывает пять приватных методов-проверок:

| Метод | Что проверяется |
|-------|-----------------|
| `checkPower()` | Питание, напряжение 12 В, POWER LED |
| `checkHdmi()` | HDMI-соединение, EDID-рукопожатие |
| `checkController()` | Bluetooth-соединение геймпада, тест осей |
| `checkStorage()` | SMART-статус встроенного SSD |
| `checkAccessories()` | Наличие кабелей и аксессуаров |

Каждый метод возвращает `bool`. Результаты агрегируются в объект `ReturnCheckResult`, который предоставляет метод `isPassed()` и форматированный отчёт `getSummary()`.

> В учебной версии все методы возвращают `true`. В реальной системе они обращались бы к физическому устройству по USB-HID или последовательному порту.

### Как фиксируются фото и видео (`ReturnMediaRecord`)

Класс `ReturnMediaRecord` хранит пути к файлам фото и видео, внешнее состояние консоли и комментарий администратора. Компьютерное зрение **не применяется**: файлы служат материалами для проверки специалистом.

Три возможных значения `externalCondition`:
- `Без повреждений` — автоматическое завершение
- `Есть следы использования` — автоматическое завершение
- `Требуется ручная проверка` — договор остаётся действующим

### Почему ручная проверка остаётся важной

Алгоритм не может заменить человека при оценке внешнего вида: царапины, потёртости, следы жидкости, трещины. Фото и видео — страховка от споров: специалист видит состояние консоли на момент возврата и принимает решение сам. Именно поэтому при статусе `Требуется ручная проверка` договор не закрывается автоматически.

### Какие классы реализуют логику

| Класс | Файл | Роль |
|-------|------|------|
| `RentalContract` | `RentalContract.h/.cpp` | Хранит данные договора, управляет его статусом |

## 13. Инструкция пользователя

### Запуск программы

После сборки запустить:
```bash
./build/ps5-rental-arm-cpp
```

### Оформление новой аренды

1. В левой части окна заполнить блок «Клиент»:
   - **ФИО** — полное имя арендатора
   - **Телефон** — номер для связи
   - **Документ** — номер паспорта или другого документа

2. В выпадающем списке **«Консоль»** выбрать доступный аппарат.  
   *Примечание: в списке отображаются только консоли со статусом «Свободна».*

3. Указать **даты аренды**: дата начала и дата окончания.

4. Выбрать количество **дополнительных геймпадов** (спиннер, 0–3).

5. Отметить чекбоксами **игры** для аренды.

6. Нажать кнопку **«Рассчитать»** — в строке ниже отобразится итоговая сумма.

7. Нажать кнопку **«Создать заказ»** — заказ добавится в таблицу со статусом «Создан».

### Управление статусами заказа

1. В таблице заказов **выбрать строку** нужного заказа (кликнуть по ней).
2. Нажать одну из кнопок управления:
   - **Начать аренду** — клиент забирает консоль
   - **Проверка возврата** — клиент вернул консоль
   - **Завершить** — проверка пройдена, аренда закрыта
   - **Отменить заказ** — заказ аннулируется

### Экспорт журнала заказов

1. Нажать кнопку **«Экспорт в CSV»** под таблицей.
2. Выбрать папку и имя файла в диалоге.
3. Файл будет сохранён в кодировке UTF-8.
