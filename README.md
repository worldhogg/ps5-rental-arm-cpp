# АРМ специалиста сервиса аренды PlayStation 5

Учебный desktop-проект: автоматизированное рабочее место (АРМ) специалиста сервиса аренды PS5. Написан на C++17, Qt 6 Widgets, с графической визуализацией на OpenGL.

---

## Цель работы

Разработать настольное приложение, автоматизирующее работу специалиста пункта проката игровых консолей PlayStation 5. Программа должна позволять вести учёт клиентов, консолей и заказов, рассчитывать стоимость аренды и управлять жизненным циклом каждого заказа.

---

## Возможности программы

### Оформление аренды
- Ввод данных клиента: ФИО, номер телефона, номер документа
- Выбор свободной консоли PS5 из трёх доступных
- Выбор дат аренды через встроенный календарь
- Подключение дополнительных геймпадов (0–3 шт., 150 ₽/день)
- Выбор дополнительных игр с чекбоксами (150–200 ₽/день каждая)
- Автоматический расчёт итоговой суммы до создания заказа
- Создание заказа одной кнопкой

### Управление заказами
- Таблица всех заказов с отображением статуса
- Переход по этапам жизненного цикла через отдельные кнопки
- Отмена заказа на любом раннем этапе

### OpenGL-визуализация
- Три карточки консолей с упрощённым силуэтом PS5
- Цвет карточки динамически меняется по статусу
- Подписи: номер консоли и текущий статус
- Автообновление при каждом изменении состояния

### Экспорт данных
- Экспорт журнала заказов в файл CSV (UTF-8)
- Сохранение через системный диалог выбора пути

## Описание основных классов

### `Client`
Хранит персональные данные клиента: ФИО, телефон, номер документа. Предоставляет геттеры и сеттеры для каждого поля.

### `ConsoleDevice`
Представляет игровую консоль PS5. Содержит: идентификатор, название, цену в сутки и статус (`ConsoleStatus`). Управляет переходами статуса при создании и завершении аренды.

### `Game`
Описывает игру для дополнительной аренды: идентификатор, название, цену в сутки.

### `RentalOrder`
Центральный класс системы. Хранит снимок клиента, снимок консоли, даты аренды, количество дополнительных геймпадов, список игр и текущий статус (`RentalStatus`). Содержит метод расчёта итоговой стоимости `getTotalPrice()`.

### `RentalManager`
Уровень бизнес-логики. Агрегирует коллекции консолей, игр и заказов. Предоставляет операции: создание заказа, переход по статусам, расчёт стоимости, экспорт в CSV. Инициализирует тестовые данные.

### `ConsoleOpenGLWidget`
Наследует `QOpenGLWidget`. Реализует отрисовку трёх карточек консолей через OpenGL Legacy: силуэт PS5, LED-линию, подписи, цветовую индикацию статуса.

### `MainWindow`
Главное окно приложения. Строит весь UI программно (без `.ui`-файлов), связывает события кнопок со слотами, управляет обновлением таблицы заказов и OpenGL-виджета.

## OpenGL-визуализация

Блок «Статус консолей» расположен в правой части главного окна. На нём через OpenGL отрисовываются три карточки — по одной для каждой консоли.

**Что рисуется на каждой карточке:**
- Фон карточки — цвет по статусу консоли
- Упрощённый силуэт PS5: белый корпус, тёмная центральная полоса, синяя LED-линия, ножки-подставки
- Надпись сверху: **PS5 #N**
- Надпись снизу: текущий статус

**Цвета по статусу:**

| Цвет | Статус консоли |
|------|----------------|
| Зелёный | Свободна |
| Синий | Забронирована |
| Оранжевый | В аренде |
| Красный | Проверка возврата |
| Серый | Недоступна |

Визуализация обновляется автоматически при любом изменении статуса консоли.

## Жизненный цикл заказа

```
Создан → Активен → Проверка возврата → Завершён
    ↘         ↘
       Отменён  Отменён
```

| Статус | Описание | Кнопка перехода |
|--------|----------|-----------------|
| `Created` | Заказ создан, консоль забронирована | — (создаётся автоматически) |
| `Active` | Консоль выдана клиенту | **Начать аренду** |
| `CheckReturn` | Клиент вернул консоль, ожидает проверки | **Проверка возврата** |
| `Completed` | Аренда успешно завершена, консоль свободна | **Завершить** |
| `Canceled` | Заказ отменён, консоль освобождена | **Отменить заказ** |

## Расчёт стоимости аренды

Формула:

```
Итого = (цена_консоли + кол_геймпадов × 150 + сумма_цен_игр) × кол_дней
```

- Цена консоли: 500 ₽/день (все три консоли)
- Дополнительный геймпад: 150 ₽/день
- Игры: 150–200 ₽/день в зависимости от названия

## Как пользоваться программой

1. **Заполните данные клиента** — ФИО, телефон, документ (все три поля обязательны)
2. **Выберите консоль** — в выпадающем списке отображаются только свободные
3. **Укажите даты** — дата начала и дата окончания аренды
4. **Выберите геймпады** — от 0 до 3 дополнительных контроллера
5. **Выберите игры** — отметьте нужные чекбоксы
6. **Нажмите «Рассчитать»** — увидите итоговую сумму
7. **Нажмите «Создать заказ»** — заказ появится в таблице
8. **Управляйте статусом** — выберите строку в таблице и нажмите нужную кнопку
9. **Экспортируйте данные** — кнопка «Экспорт в CSV» под таблицей

## Договор аренды и проверка возврата через внешний бокс

### Договор аренды

При создании нового заказа система автоматически формирует **договор аренды** (номер вида `C-0001`). Договор проходит следующие статусы:

| Статус договора | Когда наступает |
|-----------------|-----------------|
| `Подписан` | При создании заказа |
| `Активен` | После нажатия «Начать аренду» |
| `Закрыт` | После успешного завершения возврата |
| `Ручная проверка` | Если внешнее состояние требует проверки специалистом |

Договор остаётся действующим (`Активен`) до тех пор, пока возврат не пройдёт полную проверку. Если обнаружены проблемы — договор переводится в `Ручная проверка` и **не закрывается автоматически**.

### Проверочный бокс (имитация)

После того как клиент возвращает консоль, специалист нажимает **«Проверка возврата»**, переводя заказ в статус `CheckReturn`. Затем открывается блок **«Проверка возврата через бокс»**.

**Автоматическая техническая проверка** имитирует работу внешнего диагностического устройства:
- Питание (POWER LED / напряжение 12 В)
- HDMI (EDID-рукопожатие)
- Геймпад (Bluetooth + тест осей)
- Система / накопитель (SMART-статус SSD)
- Комплектность (сенсор наличия аксессуаров)

Кнопка «Запустить проверку бокса» запускает имитацию и отображает результат по каждому пункту (`OK` / `ОШИБКА`).

> В учебном проекте все проверки возвращают `OK`. В реальной системе каждый метод класса `ReturnBoxSimulator` получал бы данные от физического устройства через USB-HID или последовательный порт.

### Фото- и видеофиксация возврата

Параллельно с технической проверкой специалист фиксирует **внешнее состояние** консоли:
- Добавляет фото (`.png`, `.jpg`, `.jpeg`) через диалог выбора файла
- Добавляет видео (`.mp4`, `.mov`, `.avi`) через диалог выбора файла
- Выбирает внешнее состояние из трёх вариантов:
  - `Без повреждений` — возврат пройдёт автоматически
  - `Есть следы использования` — возврат пройдёт автоматически
  - `Требуется ручная проверка` — заказ уходит на ручную проверку
- Вводит комментарий администратора (опционально)
- Нажимает «Сохранить осмотр»

> Файлы не копируются внутрь проекта — хранятся только пути. Решение по фото/видео принимает специалист, а не алгоритм.

### Завершение аренды

Кнопка **«Завершить»** теперь проверяет три условия:

1. Автоматическая проверка бокса пройдена (`OK` по всем пунктам)
2. Осмотр сохранён (добавлено хотя бы фото или видео)
3. Внешнее состояние не равно `Требуется ручная проверка`

**Если всё в порядке:**
- Заказ → `Завершён`
- Консоль → `Свободна` (зелёная в OpenGL)
- Договор → `Закрыт`
- Сообщение: «Возврат принят. Договор закрыт.»

**Если требуется ручная проверка:**
- Заказ остаётся в `Проверка возврата`
- Договор → `Ручная проверка`
- Сообщение: «Возврат отправлен на ручную проверку. Договор остаётся действующим.»
